# Quicker HTML 动作开发提示词

请把下面方括号中的内容替换为当前项目实际信息：

```text
你正在维护一个需要运行在 Quicker 自带 WebView2 中的本地 HTML 应用。

项目目录：[绝对路径]
入口文件：[index.html 或构建入口]
构建命令：[例如 npm run build]
本次目标：[功能、故障或改造目标]

请先审计现有代码和数据流，再实施修改。遵守以下要求：

1. 优先修改 HTML、CSS、JavaScript 底层适配代码。除非我明确授权，不得创建、安装、发布或编辑任何 Quicker 动作。
2. 保留普通浏览器运行和数据读写逻辑。Quicker 专用代码必须具有浏览器回退路径。
3. 使用 `$quickerSync` 读写开启 SaveState 的 Quicker 文本变量；使用版本化 JSON 容器保存状态。所有异步写入必须等待完成并传播错误。
4. 文件选择、目录选择、任意路径写入、用默认程序打开本地文件或网址等 WebView2 不可靠能力，通过 `$quickerSp` 子程序桥接。请给出清晰的子程序名称、输入、输出、默认值和取消语义，但不要替我创建子程序。
5. 选择器的 `cancelled` 默认应为 true，只有成功选择后才改为 false。网页按钮必须在 success、cancelled、error 和异常路径下都恢复可点击。
6. 不要覆盖 Quicker 原有的 `window.chrome.webview`。宿主检测只以真实注入能力为准，不使用 user agent 猜测。
7. 外部链接采用协议白名单，拒绝 `javascript:` 和 `data:`。内部页面在 Quicker 中优先当前窗口导航。
8. 主题必须显式传递给 Mermaid 等渲染器；新增样式要验证明暗模式，不得引入浏览器与 Quicker 渲染差异。
9. 保存验证必须包含：保存数据、关闭 WebView2/动作、重新运行、确认恢复。页面内切换成功不能替代重启测试。
10. 修改前检查 Git 工作区，保留与任务无关的用户改动。精简代码前先确认所有动态引用、CSS 类、图标字体和构建复制关系。

完成后请：

- 运行语法检查、相关测试和生产构建；
- 分别报告 Quicker 与普通浏览器路径的验证结果；
- 列出我需要在 Quicker 中手工配置的变量和子程序；
- 明确说明是否使用了 C#、是否修改了 Quicker 动作；
- 如无法直接验证 Quicker UI，清楚列出最小手工验收步骤。
```
